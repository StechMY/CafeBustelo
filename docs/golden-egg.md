# 敲金蛋活动

用户入口：`/golden-egg`，首页、顶部导航和手机菜单均有入口。进入后打开全屏咖啡金蛋展示柜，GSAP 依次播放选蛋聚焦、三次锤击、裂纹加深、透光、碎片和奖品揭晓动画。底部「我的奖品」「活动规则」打开详情面板，可查看个人中奖记录和未使用的折扣券。关闭活动直接回首页，收下奖励后留在金蛋柜，不再显示第二层落地页。首页使用同一套咖啡金蛋素材活动卡。

点击金蛋先打开确认框，显示所选序号及本次消耗。点击「确认敲开」才请求服务器；取消、点击遮罩或按 Esc 均不发起抽奖、不扣次数。Agent 的次数仅作展示：进入页面显示 1–10 的随机整数，每次抽奖成功后跳到另一个 1–10 的数字，仍可持续抽奖；顶部不显示 Agent 身份文字，确认框只提示奖品即时发放。网络失败后的「找回这次抽奖」直接恢复原请求，不重复确认或扣除。

敲开后，结果页在同一座九宫柜中揭晓全部九项奖励。实际中奖奖品放在用户选择的位置并标记「你抽中」，其余八项随机放在另外八格，包含库存为 0 或权重为 0 的奖品。它们只用于本轮奖励展示，不会额外发奖，也不参与改变服务器的抽奖概率。页面只展示奖励内容，不显示库存或不可抽取状态。首页保留原来的四色胶囊操作按钮，活动卡单独排在下方。

结果金额根据可用宽度自动调整字号，超长数值允许换行，窗口缩放后会重新适配。金额保留完整货币、千分位和两位小数，不截断为省略号；十进制字符串直接格式化，避免极大金额转换成浮点数时丢失分位。

进入活动尝试播放原创咖啡馆钢琴循环；三次锤击、逐级裂壳与奖品揭晓各有同步音效。顶部声音开关统一静音并记住选择，在确认／结果弹层仍可使用；切后台或离开暂停。浏览器禁止自动播放时，首次点击活动页或“开启声音”后恢复。音频失败不会阻断抽奖。素材在 `public/audio/golden-egg/`，生成脚本为 `scripts/generate-golden-egg-audio.py`；App 接入文档包含相同素材和播放节点。

## 上线与后台配置

1. 运行 `php artisan migrate` 和 `npm run build`。
2. 后台「平台管理 → 敲金蛋活动」固定保留九个奖品位，可逐个编辑名称、现金金额或减免百分比、权重和剩余库存。「无限库存」不扣库存；有限库存为 0 或权重为 0 的奖品不会被真实用户抽中。
3. 配好奖品后，在 Admin Dashboard 的「活动与奖励 → 敲金蛋活动」开放活动，也可在奖品页的「活动设置」操作；两处读取、保存同一个开关。初始活动关闭，九个示例奖品库存均为 0，避免示例配置自动发放奖励。Dashboard 顶部入口分为「系统设置」与「活动与奖励」两个菜单，原有操作及权限继续保留。

后台权限为 `ViewAny:GoldenEggPrize`、`View:GoldenEggPrize`、`Update:GoldenEggPrize`；活动开关另需 `Manage:GoldenEgg`。超级管理员沿用现有 Shield 权限机制。

## 已确认的规则

- 活动开放期间，每笔成功购买任意产品，购买者获得一次机会。适用于全部六类产品、两种付款钱包和优惠券购买（含 100% 券）。重复购买可继续获得机会；同一购买记录的 `user_product_id` 唯一，重试不会重复发放。付款失败、历史订单、活动关闭期间的订单不发放或补发。Agent 仍使用原有持续抽奖规则，不另累计购买次数。
- 通过现有直属邀请码注册的用户，首次购买成功时活动开放，就给邀请人一次机会，不限制注册时间。网页和 API 都计入；活动开启前注册、开启后首购也符合条件。注册本身不发放；首购时创建或激活唯一的邀请记录，`qualified_at` 有值后才可使用。付款失败不发放，重复购买不重复发放邀请奖励；首购发生在活动关闭期间，后续购买不补邀请奖励。虚拟号注册或购买不产生真实邀请机会。符合条件的首购会分别给购买者和邀请人各一次机会。部署此规则不会自动重跑已经完成的历史订单。
- 真实用户每次成功抽奖扣一次机会。服务器按仍有库存且权重大于 0 的奖品重新计算相对概率，金蛋位置没有固定对应奖品。库存全部耗尽时不扣机会。
- `is_virtual` 的 agent 账号不需要邀请，无限次抽奖，九种奖品均等随机，忽略权重和库存，活动关闭时也能使用。实际发放钱包奖励／折扣券，但不扣真实库存。
- 新抽中的金额直接进入 withdrawable wallet（可提现钱包），钱包流水类型为 `golden_egg`，关联中奖记录。真实用户与 Agent 均适用；历史奖励不迁移、不重发，重试历史请求也只返回原结果。
- 折扣百分比表示原价减免比例：10% 券实付 90%。所有产品、两种购买钱包均可使用；一笔最多选择一张、每张限用一次，无到期时间。付款失败不消耗券。支持 100% 券，完全减免时不产生钱包扣款。
- 折后实付四舍五入至分，购买记录 `price_snapshot` 保存实付；原价、券 ID、减免比例和金额保存在 `meta`。产品每日收益与领取周期不变。
- 次数、奖品库存、中奖记录和发奖在同一数据库事务内处理，并锁定用户及奖品行。购买同时锁定用户、产品和优惠券，成功后标记券已使用。

## App API

App 同事／AI agent 的完整接入说明：[Flutter／App 金蛋接入](flutter-golden-egg-handoff.md)，包含入口、状态机、完整响应结构、幂等重试、钱包刷新、折扣券结账及素材清单。

以下接口沿用 `auth:sanctum`，网页另有对应的 session 路由。抽奖请求限流为每分钟 30 次。

`GET /api/v1/golden-egg` 返回 `enabled`、`is_virtual`、`remaining_chances`（agent 为 `null`）、`invite_url`、包含奖品 ID 的全部九个 `prizes`（含零库存）、最近 30 条本人 `history`、本人未使用的 `coupons`。权重和库存数量不向用户端返回。

`POST /api/v1/golden-egg/draw`：

```json
{
  "request_id": "8bfa6d71-cc46-41d2-85c4-0aeec1b3b096",
  "egg_number": 5
}
```

每次新抽奖生成一个 UUID。超时／断网后重试必须复用原 UUID，服务器返回原中奖结果，不重复扣次数或发奖。响应 `data` 为：

```json
{
  "prize": {
    "id": 1,
    "prize_id": 6,
    "egg_number": 5,
    "name": "10% purchase discount",
    "type": "coupon",
    "amount": "0.00",
    "discount_percent": "10.00",
    "created_at": "2026-10-15T10:00:00+08:00"
  },
  "remaining_chances": 2
}
```

`GET /api/v1/products` 额外返回 `data.coupons`。原购买接口可选传单个 `coupon_id`：

```json
{
  "wallet_type": "recharge",
  "coupon_id": 7
}
```

服务器校验券归属及使用状态，重新计算金额。省略／留空 `coupon_id` 沿用原价购买。活动关闭不影响已获得券的使用。

## 验证

`tests/Feature/GoldenEggActivityTest.php` 覆盖网页/API 注册不发放、活动开启前后注册均在开放期间首购发放一次、付款失败和重复购买、关闭期间首购不补发、虚拟号排除，以及机会与库存、请求重放、agent 实际发奖、发奖回滚、券快照与归属、一次性兑换、金额舍入及后台编辑。

Windows 本地 PHP 可通过 `php -d extension=pdo_sqlite vendor/phpunit/phpunit/phpunit tests/Feature/GoldenEggActivityTest.php` 临时启用 SQLite 运行。此测试显式使用内存数据库。
